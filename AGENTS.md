# AGENTS.md

## Mission

Maintain one cohesive, research-aware stack from requirements through release evidence.

These instructions govern the playbook source repository. Adoption follows `ADOPT.md`, `STACK.md`, and the target repository's own instructions.

## Start here

1. Read `README.md`, `STACK.md`, and `ADOPT.md`.
2. Inspect the current working tree before editing.
3. Keep the stack roles connected through requirement IDs and evidence links.
4. Run `python3 tools/verify_playbook.py` after changing prose, links, or sources.

## Research rules

- Label standards, empirical studies, engineering reports, documented capabilities, and James's stack choices separately.
- State the limits of empirical findings.
- Treat official tool documentation as capability evidence.
- Avoid claiming universal superiority for a selected tool or workflow.
- Keep operating choices explicit instead of deleting the stack they organise.

## Stack rules

- Keep the complete chain visible in `STACK.md` and `ADOPT.md`.
- Keep sound project equivalents through clear substitution rules.
- Put tool-specific setup in the target repository, not this source playbook.
- Use synthetic examples and data.
- Keep credentials, local reports, and generated evidence out of this repository.

## Handoff

Report changed files, checks run, exact results, research boundaries, and unresolved source questions.
